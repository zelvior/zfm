# Security policy

**ACTION REQUIRED:** GitHub private vulnerability reporting was disabled when checked on 2026-11-12; no verified private email, encryption key or response SLA is available. Do **not** post exploit details, credentials or sensitive files in public issues. Repository administrators should enable and test [GitHub private vulnerability reporting](https://docs.github.com/en/code-security/how-tos/manage-security-advisories/enable-private-vulnerability-reporting) or publish another verified confidential channel and response policy. Until then, withhold sensitive technical details; a public issue may ask maintainers for a private channel without revealing the vulnerability. Do not assume a public GitHub issue is confidential.

Reporters should include affected versions and platforms, minimal reproduction, impact and suggested mitigation only through a verified private channel once available. Please avoid testing against systems without authorization and allow time for coordinated remediation. Support for any version, response times and security fixes are not guaranteed. Back up data, avoid running untrusted archives and see [security review](LEGAL/SECURITY_REVIEW.md) for known limitations.
