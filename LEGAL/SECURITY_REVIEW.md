# Security review

**NEEDS REVIEW — limited static review, not a penetration test.** File operations and archive extraction touch attacker-controlled paths and data; native FFI, Windows shell, Linux dynamically loaded libraries, clipboard, installation directory and build scripts increase attack surface. Operations use no-overwrite and staging checks, reject some symlinks/reparse points and special files, and impose entry/depth limits; see `src/operations.rs`, `src/archive.rs` and `src/packed_archive.rs` for precise scope. These do not guarantee safety against concurrent hostile path changes. Cancellation is cooperative and failed copies may leave partial results. Archive contents remain dangerous; do not execute untrusted content. User-chosen network locations and external open handlers carry additional risks.

**ACTION REQUIRED:** threat-model untrusted directories and archive bombs/links across both platforms, review unsafe FFI and races, fuzz parsers, test adversarial archives, ensure signed release/build provenance, keep backups, and resolve private reporting channel. Avoid treating a passing test as proof of security. Do not run installer or file operations with unnecessary privileges. Review `scripts/build-linux.sh`, `scripts/build-windows.ps1` and `scripts/ci-legacy-linux.sh` downloads and mutable dependencies; pin and verify supply-chain inputs where practical without claiming existing TLS downloads have independent signatures or hashes.
